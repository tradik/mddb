# MDDB brand — usage

`brand/` is the single source of truth for the MDDB logo. Every other copy in
the repository is generated from here (or will be — see
[Consumer copies](#consumer-copies)). Edit the SVG masters by hand; never edit
a PNG, regenerate it.

## Masters

| File | What | Notes |
|---|---|---|
| `mddb-logo.svg` | The logo: a 512×512 rounded tile (`#0f172a`→`#1e293b`) carrying the cyan hex mark | Byte-identical to `docs/logo.svg`, which README and the docs site link to. Change both together; `make test-export-brand` fails when they differ. |
| `mddb-mark.svg` | The mark alone: hexagon, triangle and spark, no tile | Cut from the master by removing the tile `<rect>` and its unused gradient; viewBox `76 76 360 360`. Shapes, colours and glow are the master's. |

There is no wordmark. Where the name has to appear, set "MDDB" as live text
next to the logo in the page's own typeface rather than baking it into an image.

## Variants

- **Tile** (`mddb-logo.svg`, `icon/icon-*.png`) — the default everywhere: app
  icons, favicons, README headers, navigation. It carries its own dark ground,
  so it works unchanged on light and dark pages.
- **Mark** (`mddb-mark.svg`) — only on a dark surface (`#0f172a`–`#1e293b` or
  darker), e.g. banners and the maskable icon. Its outer cyan ring is only
  1.80:1 against white, so on a light page use the tile instead.
- Do not recolour, outline, rotate, stretch or add effects. Scale uniformly.

## Clear space and minimum size

- Keep clear space of at least **1/8 of the tile's width** on every side (64 px
  for a 512 px tile). The master already includes 32/512 of transparent margin;
  that margin counts towards it.
- Smallest tile: **16 px** (favicon). At 16 px the spark disappears and the
  triangle reads as a blob inside the ring; at 32 px hexagon and triangle are
  clear, the spark is a single bright pixel. A simplified small-size variant
  (no glow, no spark, thicker ring) would help 16 px and is out of scope for
  LOGO-000.
- Smallest mark: 48 px tall.

## Backgrounds

| Surface | Use |
|---|---|
| Light (`#ffffff` and similar) | Tile only. The tile's own `#0f172a` ground is 17.85:1 against white. |
| Dark (`#0f172a`, `#1e293b`) | Tile or mark. |
| Photos, busy patterns | Tile only, never the bare mark. |

## Colour tokens

Taken from `mddb-logo.svg`. Ratios are WCAG 2.2 contrast ratios computed from
relative luminance, `(L1 + 0.05) / (L2 + 0.05)`.

| Token | Hex | Role in the logo | vs `#0f172a` | vs `#1e293b` | vs `#ffffff` |
|---|---|---|---|---|---|
| `night` | `#0f172a` | tile top, hexagon interior | — | 1.22 | 17.85 |
| `slate` | `#1e293b` | tile bottom | 1.22 | — | 14.63 |
| `cyan` | `#00d2ff` | ring, top | 9.91 | 8.12 | 1.80 |
| `azure` | `#0072ff` | ring, bottom | 4.12 | 3.38 | 4.33 |
| `ice` | `#00f2fe` | triangle, top | 12.86 | 10.54 | 1.39 |
| `sky` | `#4facfe` | triangle, bottom | 7.37 | 6.04 | 2.42 |
| `teal` | `#00bcd4` | inner triangle | 7.77 | 6.37 | 2.30 |
| `spark` | `#ffffff` | spark | 17.85 | 14.63 | — |

What this means (SC 1.4.11 non-text contrast ≥ 3:1, SC 1.4.3 text ≥ 4.5:1):

- Every part of the mark is ≥ 3:1 against the dark tile, so the logo meets
  1.4.11 on its own ground; the weakest pair is `azure` on `slate`, 3.38:1.
- On white only `azure` reaches 3:1 (4.33:1); the other accents fail. That is
  why the bare mark is restricted to dark surfaces.
- As **text** colours: `cyan`, `ice`, `sky`, `teal` and white pass 4.5:1 on
  `night` and `slate`; `azure` does not (4.12 / 3.38) and is for large text
  (≥ 3:1) or graphics only. On white no accent passes 4.5:1 — use `night`
  (17.85:1) for text on light pages.

`icon.svg`, Airbyte `mddb.svg`, `favicon.svg`) take `mddb-logo.svg` as is.
All of `brand/` stays under 1 MB.

## Regenerating

```bash
cargo install resvg --version 0.49.0 --locked   # SVG renderer
cargo install oxipng --version 10.2.1 --locked  # lossless PNG optimiser
make brand-icons          # writes brand/icon and brand/banner
make test-export-brand    # checks them
```

ImageMagick 7 (`magick`) composes padding, banners and the `.ico`, but it does
not render the SVG: its built-in renderer (MSVG, used when librsvg is absent)
paints the master's gradients black and drops its glow. The script refuses to
run when `resvg`, `magick` or `oxipng` is missing and warns when resvg is not
the pinned version. With the pinned tools the output is byte-for-byte
reproducible, which the test checks when both are installed.
